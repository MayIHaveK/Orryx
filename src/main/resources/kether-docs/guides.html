快速开始

这一页只做一件事：确认 Orryx 已正确加载，并在游戏里成功释放一个内置示例技能。

1. 安装并首次启动

  1. 从 GitHub Releases 下载最新的 Orryx JAR。
  2. 把 JAR 放入 Paper 服务端的 plugins 目录。
  3. 完整启动一次服务器，等待 Orryx 加载完成。

首次启动或重载时，Orryx 会补齐缺失的内置配置，但不会覆盖同名文件。因此已经修改过的技能不会因为升级插件而被重置。

应该看到什么plugins/Orryx/skills/ 中会出现 JavaScript、直放、指向和被动技能示例；plugins/Orryx/stations/ 中会出现中转站示例。

2. 检查脚本环境

进入服务器后运行：

/or script environment

诊断结果会列出实际的 JavaScript 引擎、版本以及编译与执行探针。引擎状态为“可用”后，再测试内置 JavaScript 技能：

/skill cast <玩家名> JavaScript示例 1 false

成功时，目标玩家会收到包含技能等级的绿色 Orryx 消息。这个测试同时验证了技能加载、命令入口和 JavaScript 执行链路。

3. 修改与重载

打开 plugins/Orryx/skills/JavaScript示例.yml，修改消息文字，然后执行：

/or reload

再次释放技能。如果新文字出现，你的最小开发闭环已经跑通：编辑配置、重载、游戏内验证。

配置没有重新生成？内置文件只补齐缺失项。想恢复某个示例时，只删除那个示例文件再重载，不需要清空整个 Orryx 目录。

读懂技能配置

一个技能文件可以先按三层阅读：它是什么、它有哪些数值、释放后做什么。

最小技能

Options:
  Type: "DIRECT"
  Name: "练习技能"
  Icon: "练习技能"
  XMaterial: "PAPER"
  IsLocked: false
  MinLevel: 1
  MaxLevel: 5
  CastCheckAction: true
  Variables:
    MANA: 10
    COOLDOWN: 20
    SILENCE: 0

Actions: |-
  tell inline "释放成功，当前等级 {{ &level }}"
Options
技能类型、名称、图标、等级和施法检查等元数据。
Variables
在施法上下文中可复用的数值。常见的 MANA、COOLDOWN、SILENCE 分别控制消耗、冷却和沉默。
Actions
技能真正执行的 Kether 或 JavaScript 主体。

选择技能类型

类型适用场景额外关注
PASSIVE由中转站、事件或状态驱动的被动能力通常不能使用 cast 命令直接释放
DIRECT按下后立刻执行最适合从零开始验证脚本
DIRECT AIM先选落点，再执行配置瞄准半径与指示范围
PRESSING蓄力后执行配置周期、最大蓄力时间和打断条件
PRESSING AIM同时需要蓄力与落点组合两类参数，建议最后再做

Orryx 中多数持续时间按 tick 计算，20 tick 约等于 1 秒。示例中的 COOLDOWN: 20 因而约为 1 秒。

按这个顺序扩展

  1. 先把 Actions 写成一条消息，确认技能可加载。
  2. 加入一个固定伤害或效果动作。
  3. 把固定值移到 Variables，再加入等级公式。
  4. 最后补消耗、冷却、选择器和复杂流程。

遇到陌生动作时，打开左侧“语句”参考。比如 tell、damage 和 sleep 都能查看实际语法和参数。

Kether 脚本基础

Kether 很适合把技能写成一串可读的动作。先掌握值如何流动，再去组合复杂视觉效果。

顺序、变量与返回值

# 从技能变量读取伤害
set amount to lazy *DAMAGE
tell inline "本次伤害 {{ &amount }}"
damage &amount false they "@range 3 !@self" source "@self" type MAGIC
sleep 10

动作默认从上到下执行。set 把结果保存到局部变量，后续使用 &amount 读取；lazy *DAMAGE 则从技能变量中延迟求值。某些动作会返回布尔值、数字、实体或容器，具体类型以参考页为准。

条件与循环

set targets to container they "@range 5 !@self !@team"
for target in &targets[list] then {
  set hp to entity HEALTH they &target
  if check &hp > 0 then {
    damage lazy *DAMAGE false they &target source "@self" type MAGIC
  }
}

花括号包住复合动作。先把目标保存为容器，再循环处理，通常比在每一步重复执行范围选择更容易阅读和调试。

注释不会破坏行号

# 整行注释
tell "value#1" # 字符串内的 # 会保留
tell '#value'

只有单双引号外、未转义的 # 才开始注释。Orryx 会保留注释对应的换行，所以运行错误仍能指向原配置中的正确行。普通动作列表会自动包装为 def main；如果首个有效词元已经是完整的 def，则按完整脚本加载。

怎么使用参考页先在指南中理解写法，再到“语句”查看某个动作的精确参数、线程要求和返回类型。参考页负责精确，指南负责把它们串起来。

目标、容器与上下文

很多“技能执行了但没命中”的问题，并不是伤害动作出错，而是选择器没有选到预期对象。

先分清施法者和原点

@self
技能的施法者，常用于伤害来源或排除自己。
@origin
当前脚本上下文的原点。指向技能确认落点后，它通常是后续范围效果最重要的位置。
they
告诉动作“接下来这段表达式是目标”。目标可以是一个实体，也可以是选择器产生的多个实体。

从简单选择器开始

# 原点 8 格内，排除施法者、盔甲架和队友
"@range 8 !@self !@type ARMOR_STAND !@team"

选择器从几何范围开始，后面追加过滤器。调试时每次只加一个过滤条件：先确认范围内能选到实体，再逐步排除自己、实体类型和队友。

完整能力分成两个入口：“选择器”列出范围与目标构造，“属性”列出对象可读写的字段。需要复用结果时，把目标转成容器：

set targets to container they "@range 8 !@self !@team"
for target in &targets[list] then {
  tell inline "目标: {{ &target }}"
}

指向技能中的原点

DIRECT AIM 或 PRESSING AIM 确认后，脚本获得所选位置。以 @origin 创建实体或执行范围选择，效果就会围绕落点发生；使用 @self 则仍围绕玩家。

常见误区在落点创建了视觉实体，不代表后续动作会自动改用那个实体的位置。每条需要位置的动作都应明确检查自己的 origin 或 they。

指南 / 脚本

JavaScript 脚本

JavaScript 适合较长的控制逻辑和复用模块；Kether 更适合直接编排 Orryx 动作。两者可以在同一个技能中协作。

启用 JavaScript

Options:
  Type: "DIRECT"
  ScriptEngine: "JAVASCRIPT"
  CastCheckAction: "js: return player != null && player.isOnline();"
  Variables:
    MANA: "js: return 10 + level * 2;"
    COOLDOWN: "kether: math add [ 10 &level ]"

Actions: |-
  function main() {
      player.sendMessage("技能等级: " + skill.level);
      return true;
  }

脚本由 Nashorn 执行，应按 ES5.1 编写：使用 var 和 function，不要依赖箭头函数、原生 Promise 或 async/await。短字段可用 js: 或 kether: 单独覆盖主引擎。

拆到外部文件

Options:
  Type: "DIRECT"
  ScriptEngine: "JAVASCRIPT"
ScriptFile: "skills/fireball.js"

相对路径以 plugins/Orryx/scripts/ 为根。公共模块可以放到 scripts/libs/，再通过 CommonJS require("libs/math") 引入。

常用绑定包括 player、sender、parameter、skill、station、event、vars、server、scheduler、kether、orryx 和 require。

从 JavaScript 调用 Kether

function main() {
    return kether.run('tell "JS -> Kether"');
}

调度任务和循环任务应由 main 返回。这样玩家退出、脚本终止或插件重载时，Orryx 才能正确取消任务生命周期。

信任边界JavaScript 不是安全沙箱，它能接触 Bukkit、Orryx 对象和 Java 互操作能力。只加载受信任管理员维护的脚本。

指南 / 技能

指向与蓄力技能

指向技能把“按下技能”和“执行脚本”拆成两个阶段：先收集玩家选择的落点，确认后才进入 Actions。

直接指向

Options:
  Type: "DIRECT AIM"
  Name: "落点测试"
  AimRadiusAction: 20
  AimSizeAction: 8

Actions: |-
  tell "落点已确认"
  damage 20 false they "@range 3 !@self !@team" source "@self" type MAGIC

AimRadiusAction 限制可选落点距离，AimSizeAction 控制指示范围。现代服务端使用原生视线落点：左键确认，右键取消；交互会在瞄准期间被 Orryx 接管。

蓄力指向

PRESSING AIM 还会使用初始尺寸、最大尺寸、最大蓄力 tick、周期动作与打断触发器。建议先让同一份 Actions 在 DIRECT AIM 下工作，再逐项加入蓄力参数。

  1. 确认左键能落点、右键能取消。
  2. 确认 @origin 位于视线落点，而不是玩家脚下。
  3. 再加入粒子、范围目标和持续循环。
  4. 最后测试受伤打断、重复施法和超时。
现成范例无尽深渊-AI生成案例.yml 是可直接测试的 DIRECT AIM 技能，包含落点实体、范围吸引、循环伤害和斩杀判断。

指南 / 实践

从内置示例继续开发

内置示例不是只用来证明插件启动成功，它们分别展示了不同的技能结构。复制最接近需求的一份，再逐步替换。

技能目录里的四条路线

文件适合学习测试方式
JavaScript示例.ymlJS 引擎、短字段覆盖和 main()直接 cast
裂焱冲击-AI生成案例.yml位移、药水效果、路径循环伤害直接 cast
无尽深渊-AI生成案例.yml指向落点、实体、容器、范围吸引和循环cast 后左键确认
无畏护盾-AI生成案例.yml被动技能与事件驱动的职责分离配合中转站触发

测试直放或指向技能时使用：

/skill cast <玩家名> <技能名> 1 false

为什么护盾拆成多份文件

被动技能只描述等级和变量；“多久未受击”“什么时候创建护盾”“受到伤害如何扣除护盾”由中转站监听相应事件。这样每个文件只负责一种触发时机，也便于单独关闭和排错。

stations/example.yml 默认禁用，避免演示监听器在生产服反复输出。需要启用某个中转站时，明确设置 Options.Enabled: true，然后执行 /or reload。

安全的改造顺序

  1. 复制文件并先改文件名、Options.Name 和图标。
  2. 重载并确认新技能能被单独识别。
  3. 一次只替换一个变量或动作段，每次都进游戏验证。
  4. 最后再调整伤害、消耗、范围和冷却的平衡数值。

指南 / 运维

调试与排错

先确定问题发生在哪一层，再改配置。下面的顺序能避免在动作脚本里追查一个其实由文件加载引起的问题。

第一层：文件是否存在

检查 plugins/Orryx/skills/ 与 plugins/Orryx/stations/。缺失的内置文件会在启动或重载时补齐，同名文件则不会被覆盖。若只缺某个范例，删除或移动对应同名文件后再执行 /or reload。

第二层：配置是否加载

  1. 查看重载时控制台最先出现的 YAML 或脚本错误。
  2. 把 Actions 暂时缩减成一条 tell，确认技能入口正常。
  3. 检查技能名是否与 cast 命令完全一致。
  4. 被动技能应检查中转站是否启用，不能只靠 cast 命令判断。

第三层：脚本执行到哪里

在关键步骤之间临时加入 tell，逐段定位中断位置。目标相关问题先移除过滤器，只保留一个范围选择；确认有结果后再逐个加回 !@self、!@team 等条件。

JavaScript 问题先运行：

/or script environment

然后确认代码是 Nashorn ES5.1 写法，并且包含 function main()。外部文件路径始终相对 plugins/Orryx/scripts/。

最小复现模板

Options:
  Type: "DIRECT"
  Name: "排错技能"
  IsLocked: false
  MinLevel: 1
  MaxLevel: 1
  CastCheckAction: true
  Variables:
    MANA: 0
    COOLDOWN: 0
    SILENCE: 0
Actions: |-
  tell "step-1"
  sleep 1
  tell "step-2"

把有问题的动作逐段移入这个模板。最小版本能工作时，问题通常就在刚加入的那一段或它依赖的上下文中。
